# HUMAN STEPs

Everything below needs a login, a credential or a legal approval. Start 5 (carrier registration) and 7 (Meta app review) on day one — they take days to weeks.

| # | Where | What to do | Result goes to |
|---|---|---|---|
| 1 | GitHub | Create a private repo and push this one (`git remote add origin … && git push -u origin main`). Add secrets `STAGING_DATABASE_URL` and (optional) `ANTHROPIC_API_KEY` for CI. | Repo for Railway |
| 2 | Supabase | Create a project. Enable Auth: email magic link + Google provider; set Site URL to `APP_URL` and add `APP_URL/auth/callback` as a redirect. Turn on Realtime for tables `messages`, `leads`, `appointments`. Turn on daily backups + PITR for production. Run `DATABASE_URL=… npm run db:migrate` (no `--shim`). | `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `DATABASE_URL` (session pooler) |
| 3 | Railway | Project with two services from the repo: `web` (uses `railway.json`) and `worker` (start command `npm run worker`). Staging + production environments. Set all env vars from `.env.example`; generate `ENCRYPTION_KEY` with `openssl rand -base64 32`. Keep `DEV_LOGIN` unset. | Deploy target |
| 3b | Registrar | Buy the app domain, point it at the Railway web service. | `APP_URL` |
| 4 | Anthropic Console | Create an API key. Then run `npm run evals` — must be ≥ 90% before go-live. | `ANTHROPIC_API_KEY` |
| 5 | Twilio | Upgrade, complete the ISV primary business profile in Trust Hub. Per pilot org: buy a local number, create a Messaging Service with Advanced Opt-Out ON, inbound URL `APP_URL/api/webhooks/twilio/sms`, status callback `APP_URL/api/webhooks/twilio/status`; submit A2P brand + campaign using the details from the onboarding "Phone number" step. When approved, set the org's number in Settings → Integrations and flip "texting enabled" in /admin. Buy one more number for rep alerts. | `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_ALERT_NUMBER`, `PLATFORM_ALERT_PHONE` |
| 6 | Postmark | Create a server; verify the sending domain (e.g. `mail.<appdomain>`); create a broadcast stream named `broadcast`; turn on inbound with webhook `APP_URL/api/webhooks/postmark/inbound?token=<secret>` and an inbound domain (MX record). | `POSTMARK_SERVER_TOKEN`, `POSTMARK_SENDING_DOMAIN`, `POSTMARK_INBOUND_DOMAIN`, `POSTMARK_INBOUND_WEBHOOK_SECRET` |
| 7 | Meta for Developers | Business app with Facebook Login for Business (create a configuration with the lead-ads permissions, e.g. `leads_retrieval`, `pages_show_list`, `pages_read_engagement`, `pages_manage_metadata`, `ads_read` for spend), Webhooks (Page → `leadgen`, callback `APP_URL/api/webhooks/meta`, verify token), Marketing API. Business verification + app review. Until approved: per pilot, a Zap from Facebook Lead Ads → Webhooks POST to the org's intake URL (Settings → Integrations), mapping lead id, form id, campaign/ad names, name, phone, email and all answers. | `META_APP_ID`, `META_APP_SECRET`, `META_LOGIN_CONFIG_ID`, `META_WEBHOOK_VERIFY_TOKEN`, `META_GRAPH_VERSION` |
| 8 | Google Cloud | OAuth client (web) with Calendar API enabled; redirect `APP_URL/api/integrations/google/callback`; submit the consent screen for verification. | `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` |
| 9 | TCPA attorney | Review consent language, opt-out handling (`lib/compliance/optOut.ts`), quiet hours and caps (`sendWindow.ts`, `state-rules.ts`), retention/deletion, customer terms. Sign-off before `DRY_RUN=false`. | Sign-off |
| 10 | BMW of Elmhurst | Answer the open questions in docs/SPEC.md (deposit, arrival windows, configurations, incentives, hours/address/specialists, credit link, pricing policy, consent disclosure on each form, CRM + ADF address). Enter them as knowledge items. | Knowledge base |
| 11 | Product owner | Review 20 simulator conversations, keep approve-before-send on for 2 weeks, then set `DRY_RUN=false` in production. | Go live |
